                           BUSINESS OVERVIEW
================================================================================

PROBLEM STATEMENT
-----------------
INSY2S faced fragmented incoming requests across multiple channels (email,
WhatsApp, web forms) each operating in isolation. Support agents spent
excessive time on manual data entry, context switching between channels,
and hand-typing information from attached documents (invoices, passports,
complaints). This led to information dispersion, extended response times,
human error, and GDPR compliance risks.

SOLUTION
--------
A unified omnichannel platform that centralizes, automates, and intelligently
processes customer requests from multiple channels into a single ticket system
with AI-powered analysis, document OCR, and automated reply generation.

KEY BUSINESS RESULTS
--------------------
  - Processing speed:  ~20 min (manual) → ~3 sec (automated) — 300x faster
  - Automation rate:   78% of requests processed without human intervention
  - OCR accuracy:      94.3% across diverse document types
  - Cost reduction:    73% reduction in operational cost per request
  - System uptime:     99.8% availability during testing

CORE MODULES
------------
  1. Multi-Source Ingestion
     - Email (IMAP with OAuth2), WhatsApp Business API, Web Forms, REST API
     - All channels normalized into a unified ticket format

  2. Document Management & OCR
     - Multi-engine pipeline: Tesseract (FR/EN) + EasyOCR (Arabic)
     - Preprocessing: deskewing, contrast, resolution normalization
     - Structured extraction: invoices, passports (MRZ), complaints
     - Confidence scoring with automated quality checks

  3. AI Analysis & Response Engine
     - BERT-based classification (5 categories: Complaint, Invoice, Quote,
       Technical Support, HR) trained on 5,000+ historical tickets
     - Confidence-scored routing: high confidence → auto-process; low → human
     - Priority detection via urgency signals (keywords, deadlines, history)
     - Named entity recognition (persons, orgs, phones, references)
     - LLM-powered reply generation (RAG pipeline) — multilingual AR/FR/EN

  4. Back-Office Management Interface
     - Agent dashboard: ticket queue, filtering, side-by-side document view
     - Data correction, internal notes, escalation workflows
     - One-click response sending through original channel

  5. Backup & Archiving
     - AES-256 encrypted document storage (MinIO)
     - Full-text search via Elasticsearch
     - GDPR compliance: right to erasure, data portability

================================================================================
                        ARCHITECTURE
================================================================================

Pattern: Hybrid Microservices with Event-Driven Architecture

CORE DOMAIN SERVICES (6):
  - request-service        (ticket lifecycle — Spring Boot)
  - document-ocr-service   (OCR processing — Python/Flask)
  - ai-analysis-service    (classification & NLP — Python)
  - llm-service            (reply generation with RAG — Python/FastAPI)
  - response-workflow      (decision engine: auto vs. assisted)
  - ingestion-service      (channel normalization)

CROSS-CUTTING SERVICES (6):
  - member-service         (user accounts, role sync with Keycloak)
  - notification-service   (multi-channel alerts)
  - ged-service            (document storage on MinIO)
  - email-service          (outbound SMTP delivery)
  - security               (Keycloak IAM)
  - evaluation-service     (satisfaction surveys)

KEY DESIGN DECISIONS
--------------------
  - Event-driven via Kafka with manual offset commits
  - CQRS-like: PostgreSQL (current state) + Kafka (append-only event log)
  - RAG pipeline: Processing → Retrieval → Generation → Validation
  - Human-in-the-loop: confidence thresholds for auto vs. assisted routing
  - Multi-OCR fallback chain with automatic language detection
  - Blue-green deployment for n8n workflows
  - Sub-workflow composition in n8n (DRY principle)
